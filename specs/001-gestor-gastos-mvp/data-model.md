# Data Model: Gestor de Gastos MVP

**Date**: 2026-10-15
**Source**: [spec.md](./spec.md)
**Representation rule**: Every ARS or USD value is an integer number of cents in persistence and a
canonical two-decimal string at the HTTP boundary. No monetary field uses floating point.

## Shared conventions

- Primary keys are opaque UUID strings generated by the backend.
- `created_at` and security timestamps are UTC instants. Expense and purchase dates are calendar
  dates interpreted using `America/Argentina/Buenos_Aires` when omitted.
- Every mutable aggregate has `version` starting at 1. Successful updates increment it; a stale
  version fails with a conflict and does not mutate data.
- Every table relationship enforces foreign keys. Board-scoped relationships carry enough board
  context to prevent cross-board references.
- Hard deletion is used only for expenses and USD purchases because the spec removes them from
  current history after confirmation. Guest participants are retired, not physically deleted.
- Derived values such as debts, category totals, consumed money, remaining money and total savings
  are not stored.

## Entity relationship overview

```text
User 1──* AuthSession
User 1──* PasswordResetToken
User 1──* Membership *──1 Board 1──1 BoardInvitationState
Membership 1──1 BoardPerson(account)
Board 1──* BoardPerson(guest/account)
Board 1──* Expense 1──* ExpenseShare *──1 BoardPerson
Board 1──* MonthlyBudget
Board 1──0..1 InitialSavings
Board 1──* UsdPurchase
```

## User

Represents an authenticated account.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| id | UUID string | yes | Immutable primary key |
| display_name | string | yes | Trimmed, 1–100 characters |
| email | string | yes | Trimmed, normalized to lowercase for identity; globally unique |
| password_hash | string | yes | Argon2 hash only; never returned |
| created_at | UTC datetime | yes | Set on registration |

**Relationships**: Has sessions, reset tokens and memberships. Its visible name is used by linked
account people; email is exposed only where homonyms need disambiguation.

**Validation/invariants**:

- Password input has at least 8 characters, but plaintext never becomes a persisted field.
- Duplicate normalized email is rejected atomically.

## AuthSession

Represents one revocable JWT login.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| id / jti | UUID string | yes | Primary key and JWT `jti` |
| user_id | UUID string | yes | FK to User; indexed |
| issued_at | UTC datetime | yes | Matches JWT `iat` |
| expires_at | UTC datetime | yes | 30 minutes after issue |
| revoked_at | UTC datetime | no | Set by logout or password reset |

**State transitions**: `active → expired` by time; `active → revoked` by logout/reset. Expired or
revoked sessions cannot authenticate.

## PasswordResetToken

Stores only the digest of a one-time recovery token.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| id | UUID string | yes | Primary key |
| user_id | UUID string | yes | FK to User; indexed |
| token_digest | fixed hex string | yes | SHA-256 digest; unique; raw token never stored |
| created_at | UTC datetime | yes | Issue instant |
| expires_at | UTC datetime | yes | Exactly 30 minutes after issue |
| used_at | UTC datetime | no | Set atomically on successful reset |

**State transitions**: `issued → expired`, or `issued → used`. A used, expired or unknown token is
rejected with the same generic error. Successful reset also revokes all active AuthSession rows for
the user and invalidates other unused reset tokens.

## Board

Root aggregate and authorization boundary.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| id | UUID string | yes | Immutable primary key |
| name | string | yes | Trimmed, 1–100 characters; need not be globally unique |
| created_at | UTC datetime | yes | Creation instant |

**Relationships**: Owns memberships, people, invitation state, expenses, monthly budgets and
savings records.

## Membership

Links one account to one board; all memberships have equal capabilities.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| id | UUID string | yes | Primary key |
| board_id | UUID string | yes | FK to Board |
| user_id | UUID string | yes | FK to User |
| joined_at | UTC datetime | yes | Creation/join instant |

**Constraints**: Unique `(board_id, user_id)`. Creating a board creates its first membership and
account BoardPerson atomically. Joining an existing membership is idempotent and creates no duplicate.

## BoardPerson

Unified identity for a payer or share recipient.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| id | UUID string | yes | Primary key |
| board_id | UUID string | yes | FK to Board; part of board-scope constraints |
| kind | enum | yes | `account` or `guest` |
| user_id | UUID string | conditional | Required and unique per board for `account`; null for `guest` |
| guest_name | string | conditional | Required, trimmed 1–100 chars for `guest`; null for `account` |
| active | boolean | yes | Defaults true; account persons remain active while membership exists |
| version | integer | yes | Optimistic concurrency token |
| created_at | UTC datetime | yes | Creation instant |
| retired_at | UTC datetime | no | Set only when a guest is retired |

**Derived presentation**: Account name/email come from User. Guest name comes from `guest_name`.
Homonyms are allowed; account email and stable person IDs disambiguate selection. The same person
cannot appear twice in one expense distribution.

**State transitions**: Guest `active → retired`; no reactivation flow in the MVP. Retired guests
remain queryable in historical expenses and are excluded from new payer/participant choices.

## BoardInvitationState

Maintains the single reusable invitation capability for a board.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| board_id | UUID string | yes | PK/FK to Board; one-to-one |
| nonce | random bytes/encoded string | yes | Rotated after expiry |
| issued_at | UTC datetime | yes | Start of validity |
| expires_at | UTC datetime | yes | Seven calendar days after issue |
| version | integer | yes | Protects concurrent rotation |

**Derived code**: HMAC of board identity, nonce and expiry using an environment secret. The code is
reproducible while current, not stored as plaintext and invalid when signature, expiry or current
nonce does not match.

**State transitions**: `valid → expired` by time; first request after expiry atomically rotates the
nonce and returns the new 7-day code.

## Expense

Confirmed ARS movement.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| id | UUID string | yes | Primary key |
| board_id | UUID string | yes | FK to Board; indexed with `expense_date` |
| name | string | yes | Trimmed, 1–150 characters |
| amount_ars_cents | integer | yes | Greater than 0 |
| category | enum | yes | `food`, `transport`, `housing`, `services`, `health`, `education`, `leisure`, `other` |
| expense_date | date | yes | Supplied or defaulted in Argentina timezone |
| payer_person_id | UUID string | yes | Active BoardPerson in same board at creation/edit |
| expense_type | enum | yes | `personal`, `equal`, `custom` |
| description | string | no | Trimmed; maximum 1000 characters |
| version | integer | yes | Optimistic concurrency token |
| created_at | UTC datetime | yes | Creation instant |
| updated_at | UTC datetime | yes | Last successful update |

**Relationships**: Has one or more ExpenseShare rows. Payer and every share person belong to the
same board. Historical references may point to a now-retired guest.

**Validation/invariants**:

- Shares sum exactly to `amount_ars_cents` and none is negative.
- `personal`: exactly one share, payer receives the full amount.
- `equal`: at least one selected person; base share and residual cents follow stable
  `selection_order`.
- `custom`: at least one selected person; caller supplies exact shares.
- Edit replaces the share set atomically after validating the final aggregate.
- Delete removes expense and shares in one transaction after the UI confirmation and version check.

## ExpenseShare

Exact portion of an expense assigned to one person.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| id | UUID string | yes | Primary key |
| expense_id | UUID string | yes | FK to Expense; cascade on expense deletion |
| board_id | UUID string | yes | Matches Expense and BoardPerson board |
| person_id | UUID string | yes | FK to BoardPerson in same board |
| amount_ars_cents | integer | yes | Greater than or equal to 0 |
| selection_order | integer | yes | Zero-based, unique inside expense |

**Constraints**: Unique `(expense_id, person_id)` and `(expense_id, selection_order)`. A person's
debt is this amount when `person_id != payer_person_id`; the payer's own share creates no debt.

## MonthlyBudget

Optional ARS base for one board month.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| id | UUID string | yes | Primary key |
| board_id | UUID string | yes | FK to Board |
| year | integer | yes | Four-digit supported calendar year |
| month | integer | yes | 1–12 |
| base_ars_cents | integer | yes | Greater than or equal to 0 |
| version | integer | yes | Optimistic concurrency token |
| created_at | UTC datetime | yes | Creation instant |
| updated_at | UTC datetime | yes | Last update |

**Constraints**: Unique `(board_id, year, month)`.

**Derived monthly summary**:

- `consumed_ars_cents = sum(expense.amount_ars_cents) + sum(usd_purchase.ars_spent_cents)` for
  movement dates in the month.
- If a budget exists, `remaining_ars_cents = base_ars_cents - consumed_ars_cents`, including
  negative values.
- If absent, consumed remains available and remaining is `null`/“not available”; absence never
  creates a zero budget.

## InitialSavings

Optional single USD opening balance for a board.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| board_id | UUID string | yes | PK/FK to Board; enforces one current record |
| amount_usd_cents | integer | yes | Greater than or equal to 0 |
| version | integer | yes | Optimistic concurrency token |
| created_at | UTC datetime | yes | Creation instant |
| updated_at | UTC datetime | yes | Last update |

**State transitions**: `absent → present` on creation, `present → present` on edit,
`present → absent` on deletion.

## UsdPurchase

Purchase that increases USD savings and consumes ARS in its month.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| id | UUID string | yes | Primary key |
| board_id | UUID string | yes | FK to Board; indexed with `purchase_date` |
| amount_usd_cents | integer | yes | Greater than 0 |
| ars_spent_cents | integer | yes | Greater than 0 |
| purchase_date | date | yes | Supplied or defaulted in Argentina timezone |
| version | integer | yes | Optimistic concurrency token |
| created_at | UTC datetime | yes | Creation instant |
| updated_at | UTC datetime | yes | Last update |

**Derived total savings**: current InitialSavings amount or zero, plus
`sum(UsdPurchase.amount_usd_cents)` across all current purchases. No exchange rate or ARS valuation
is stored or derived.

## AudioProposal (transient value object)

Returned by audio processing but never persisted.

| Field | Type | Required | Rules |
|-------|------|----------|-------|
| transcript | string | no | Used for review; not logged or persisted |
| name | string | no | Extracted candidate |
| amount_ars | decimal string | no | Canonical when recognized |
| category | enum | no | Fixed catalog value when recognized |
| expense_date | date | no | Extracted/defaulted only when unambiguous |
| description | string | no | Extracted candidate |
| expense_type | enum | no | Extracted candidate |
| payer_person_id | UUID string | no | Only when exactly matched in board context |
| participant_person_ids | UUID string list | no | Stable extracted order |
| custom_shares | list | no | Person IDs and canonical amount strings |
| missing_fields | string list | yes | Required fields not confidently extracted |
| ambiguities | object list | yes | Field, source text and candidate person IDs/values |
| warnings | string list | yes | Non-blocking interpretation issues |

**Lifecycle**: `captured → processing → proposed → edited → confirmed/discarded`. Confirmation sends
the edited data through the normal Expense creation contract; it does not mutate this object.
Temporary audio is deleted in a `finally` cleanup path after response or failure.

## Referential and authorization invariants

1. Every board-scoped command begins by proving `(board_id, actor_user_id)` membership.
2. Every resource query includes both its ID and board ID; foreign-board and missing IDs yield the
   same public result.
3. Payer and share people must belong to the same board as the expense.
4. Only active people may be selected for new or edited expenses; historical reads include retired
   people.
5. No repository method commits independently; the application use case commits the full state
   transition or rolls it back.
6. Mutations compare `version`; stale requests make no changes and return a conflict.
